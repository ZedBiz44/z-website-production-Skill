# Runtime and Platform Use
Use the installed runtime's supported tools. This is an instruction workflow, not a new browser, hosting service or CMS connector.

## OpenClaw
Use the current browser plugin and its installed guidance for rendered pages, snapshots, screenshots, viewports and harmless interaction. Discover tool names instead of assuming them from another runtime. Page extraction alone cannot verify JavaScript interaction.
For installation checks select the actual agent owner with skills commands. Use a fresh isolated session for pilots; do not deliver test messages to a business channel.
Production uses an authorized operator's existing platform connector or approved project/file workflow. Verify read/edit/preview/test/recovery capabilities in that operator's runtime before promising output.
If browser or builder access is missing, return the useful partial result and precise unavailable capability. Do not change gateway configuration or install a connector as an incidental repair.

## Other runtimes and builders
The core and records are portable. Use native discovery and tools; do not copy OpenClaw commands into another runtime.
Compatibility is demonstrated only for the runtime and builder routes in the release evidence. WordPress, GoHighLevel and AI builders need their own verified execution route; matching design principles do not prove connector access.

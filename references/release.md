# Review, Release and Maintenance
## Review
Always inspect the actual resulting artifact. Scope tests to the change: content-only text/display; local layout responsive states; shared components representative instances/journeys; integrations permitted test input and destination; releases destination/version/recovery.
Separate review is mandatory when the brief requires it. An authorized equivalent reviewer can use the same criteria; otherwise label self-review. Missing companions do not prevent useful work, but missing required checks prevent the corresponding readiness claim.
Retain stable findings and states. Only evidence closes a finding. Two correction passes are a normal allowance, not forced approval or a reason to abandon an obvious authorized fix.

## Test manifest
Record browser/device, viewport, zoom, input method, login state, artifact version, tool/rule set, expected result, actual result, evidence and untested states.
Use synthetic data and permitted test accounts/recipients. Verify receipt when authorized; otherwise state delivery pending. Never test real charges, contacts or bookings without explicit authority.
Use basic accessibility checks unless a named standard and full audit were actually in scope. Font/image rights and approved factual claims need their own evidence.

## Release and recovery
Before a material release name the approving person, exact version, public destination, prior working version, recovery owner/method and success check.
Stop/rollback triggers: broken primary journey, widespread shared-template regression, severe content loss or wrong public destination.
Use only an authorized restoration, preserve new business records, and choose the least destructive method. Do not blindly restore a full database over fresh enquiries or orders.
Check redirects, internal links, canonical addresses and intended indexing when relevant, including preview-to-live differences.
A preview-only assignment remains a preview. No live domain connection, public publication, email or recurring service is implicit.

## Maintenance
Read the current project record, inspect changed areas, apply the authorized correction with appropriate recovery, retest dependencies and update the completion record.
Name the content/update owner, current version, dependencies needing attention and next review trigger. Add cadence only for explicitly recurring work.
Use a baseline and success signal when meaningful; function, usability and business outcome are separate evidence claims.
